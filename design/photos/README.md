# Портреты персон

Два пути. Ручной — залить файл сюда. Автоматический — вписать персону
в `content/photo-sources.json` и запустить workflow; тогда снимок скачается
из первоисточника вместе с автором и лицензией.

## Автоматически: список источников

Для публичных фигур со статьёй в Википедии достаточно названия статьи:

```json
[
  { "slug": "sergej-lavrov", "wikipedia": "Лавров, Сергей Викторович" },
  { "slug": "kto-to", "commons": "File:Имя файла.jpg" },
  { "slug": "geroj", "url": "https://…", "license": "предоставлено героем",
    "author": "И. Фотографов", "source_url": "https://…" }
]
```

Режим `wikipedia` идёт по цепочке: статья → элемент Викиданных → свойство
P18 «изображение». P18 — выбранный сообществом основной портрет, поэтому имя
файла не приходится угадывать, а кадр почти всегда пригоден. Режим `commons`
нужен, когда портрет из P18 не устраивает и файл выбран вручную.

Запуск — вкладка **Actions → «Портреты персон» → Run workflow**. Раннер
скачивает снимки, кадрирует, проверяет целостность контента, пересобирает
индекс поиска и коммитит результат в ту же ветку. Локально скрипт не
работает: среде разработки закрыт доступ к внешним хостам.

Если точное название статьи неизвестно, скрипт ищет её по Википедии — но
берёт результат, только когда в заголовке нашлись и имя, и фамилия персоны.
Иначе он отказывается: поиск возвращает ближайшее совпадение, а не точное,
и однажды по запросу «Ивлеева, Анастасия Владимировна» выдал «Гордеева,
Катерина Владимировна» — совпало отчество. Портрет чужого человека на
биографии хуже, чем отсутствие портрета.

Кадрирование по умолчанию — «по вниманию»: sharp сам ищет значимую область,
и для портрета это почти всегда лицо. На широких снимках он ошибается —
на кадре с пресс-конференции «вниманием» оказались микрофоны. Тогда
добавляется `"gravity": "centre"` (или `north`, `west`, `east`).
Про горизонтальный исходник скрипт предупреждает сам.

Автор и лицензия берутся из API Викисклада, а не переписываются руками:
переписанная атрибуция при свободной лицензии означала бы нарушение её
условий. Снимок с несвободной лицензией скрипт отклоняет — «нашлось
в интернете» основанием не является.

## Вручную: файл в этой папке

Один файл на персону. **Имя файла — слаг персоны**, расширение любое:

```
design/photos/andrej-mejster.png
design/photos/sergej-lavrov.jpg
```

Слаг берётся из очереди — колонка «Слаг» в `/lk/ochered/` или поле `slug`
в `content/persons/<slug>.json`. Если имя файла не совпадает со слагом,
ничего страшного: путь всё равно указывается в команде явно.

## Что дальше

```bash
npm run photo -- andrej-mejster design/photos/andrej-mejster.png \
  --author="Пресс-служба МИД России" \
  --license="CC BY 4.0" \
  --source="https://www.mid.ru/..."
```

Скрипт кадрирует в 4:5 по лицу, приводит к 1200×1500, применяет единую
коррекцию и прописывает снимок в карточку персоны вместе с данными о правах.

## Требования к исходнику

- **Минимум 1200×1500.** Меньше — портрет будет растягиваться и потеряет
  резкость; скрипт об этом предупредит, но не откажется.
- Портретная или квадратная ориентация, лицо в верхней трети кадра.
- Фон нейтральный или размытый, естественный свет.
- Без тяжёлых фильтров, виньеток и надписей: единая коррекция применяется
  ко всем портретам, чтобы галерея выглядела одним каталогом.

## Права — обязательно

Права на фотографию принадлежат фотографу. Снимок из поиска брать нельзя:
это нарушение, а для портала, который продаёт размещение, ещё и прямой риск.

Законные источники:

| Источник | Что писать в `--license` |
|---|---|
| Фотография от самого героя | `предоставлено героем` |
| kremlin.ru, government.ru | `CC BY 4.0` + `--author` и `--source` |
| Викисклад со свободной лицензией | точное обозначение лицензии со страницы файла |
| Фотобанк | `фотобанк <название>`, лицензия хранится у редакции |

Без `--license` проверка `npm run check:content` не пропустит публикацию —
это ошибка, а не предупреждение. Автор и лицензия выводятся подписью под
портретом: свободные лицензии этого прямо требуют.
